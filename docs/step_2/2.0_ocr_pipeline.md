# Step 2.0 — OCR Pipeline

## PDF rendering

`src/ocr_eval/pdf_utils.py` converts PDF pages into deterministic image inputs. This creates a stable boundary between document input and OCR execution.

The same collection mechanism can also accept image inputs.

## OCR adapter

`PaddleOCRAdapter` isolates engine-specific behavior.

The adapter:

1. resolves the requested execution device;
2. initializes PaddleOCR;
3. processes page images;
4. converts engine results into the project's OCR schema;
5. records runtime metadata.

## Why the adapter boundary matters

A future OCR engine can be introduced behind the same boundary without rewriting the evaluation algorithms.

This is particularly important because OCR quality evaluation should not be coupled to one engine's native result format.

## Raw output

`scripts/run_ocr.py` writes machine-readable OCR results containing the normalized document representation and execution metadata.

These raw outputs are inputs to later evaluation/reporting workflows.
