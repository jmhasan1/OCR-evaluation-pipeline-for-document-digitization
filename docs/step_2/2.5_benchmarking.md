# Step 2.5 — CPU/GPU Portability and Benchmarking

Step 2.5 adds execution portability and runtime measurement without changing the evaluation algorithms.

## Device modes

The OCR adapter supports:

- `cpu`
- `gpu:0`
- `auto`

`auto` uses a GPU when Paddle reports CUDA availability. Explicit GPU requests fail clearly when the requested GPU execution cannot be provided.

## Runtime metadata

OCR execution records:

- requested device
- resolved device
- GPU availability
- GPU name when available
- Paddle version
- PaddleOCR version
- initialization time
- inference time

## Benchmarking

`scripts/benchmark_ocr.py` measures:

- warmup runs
- measured runs
- mean/median/min/max inference time
- per-page latency
- pages per second
- GPU memory where available

Performance and quality are deliberately kept separate:

> A faster OCR configuration is not automatically a more accurate or safer configuration.

## Current benchmark evidence

The repository contains development benchmark artifacts for `doc_001`.

Representative recorded results include:

| Mode | Mean inference | Pages/sec |
|---|---:|---:|
| CPU | 126.2645 s | 0.01584 |
| GPU | 3.6346 s | 0.550273 |

These are measurements for the recorded development benchmark environment and should not be generalized to other hardware.
