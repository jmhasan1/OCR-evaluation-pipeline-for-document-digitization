# Step 2.5.1 — Execution Architecture

The repository separates reusable components from workflow scripts.

```text
scripts/
    workflow orchestration
        ↓
src/ocr/
    OCR engine boundary
        ↓
src/ocr_eval/
    reusable evaluation primitives
        ↓
tests/
    regression and contract validation
```

## Script responsibilities

Examples:

- `run_ocr.py` — OCR execution.
- `benchmark_ocr.py` — runtime benchmarking.
- `environment_check.py` — environment diagnostics.
- `render_documents.py` — development document rendering.
- `validate_ground_truth.py` — synthetic reference validation.

Later steps add evaluation/reporting workflows without moving engine-specific logic into scripts.

## Why this separation matters

It supports:

- testability
- reuse
- deterministic behavior
- clearer ownership of failures
- future engine substitution
- evaluator-facing reproducibility
