# Step 3.3 — Faithfulness and Reporting

Faithfulness is evaluated separately from OCR accuracy.

## Two different questions

**OCR accuracy**

> Did OCR recognize the source text correctly?

**Faithfulness**

> Does downstream output remain supported by the source OCR/content?

The distinction matters because a downstream document-AI component can alter or rewrite information even when the source OCR output is fixed.

## Implementation

`src/ocr_eval/faithfulness.py` provides the structured comparison result.

`src/ocr_eval/faithfulness_reporting.py` adds:

- tokenization
- token-level differences
- human-readable difference reporting
- machine-readable serialization

The reporting layer is designed for CLI/evaluator inspection without changing the core comparison contract.

## Testing

The faithfulness tests validate:

- identical text
- meaningful differences
- normalized comparisons
- token-level reporting
- serialization
- adversarial cases

The subsystem is intentionally small and composable rather than being embedded into the OCR pipeline.
