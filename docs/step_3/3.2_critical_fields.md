# Step 3.2 — Critical-Field Extraction and Evaluation

## Purpose

A document can have an acceptable aggregate text score while containing a serious error in one important identifier.

The project therefore evaluates critical fields separately.

## Extracted field classes

The rule-based extractor supports fields including:

- owner/purchaser names
- father/husband names
- survey/plot/khasra numbers
- area and unit
- village
- tehsil
- district
- registration number and date
- mutation number and date

## Extraction

`src/ocr_eval/extraction.py` uses label-aware and structure-aware rules rather than arbitrary positional inference.

It supports:

- scalar fields
- list fields
- structured area values
- multiple sellers
- wording variants
- explicit missing values
- OCR-preserved identifiers

## Evaluation

`src/ocr_eval/critical_fields.py` distinguishes:

- `exact_match`
- `normalized_match`
- `mismatch`
- `missing`

This makes critical consequences visible even when aggregate CER/WER is small.

## Testing strategy

Tests cover:

- identifier corruption
- missing fields
- nearby annotations
- multiple sellers
- whitespace variation
- date-format variation
- punctuation preservation
- avoidance of silent OCR correction
