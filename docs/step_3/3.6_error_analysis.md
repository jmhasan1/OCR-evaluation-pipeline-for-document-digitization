# Step 3.6 — Error Analysis and Reporting

## Purpose

The error-analysis layer consolidates existing evaluation outputs rather than introducing another independent accuracy metric.

Implemented by:

```text
scripts/analyze_errors.py
tests/test_analyze_errors.py
```

## Error categories

Current categorization includes:

- `character_level`
- `whitespace`
- `punctuation`
- `identifier`
- `field_level`
- `faithfulness`
- `real_data_observation`

The categories connect observable failures to likely downstream consequences.

## Reporting

The analysis produces:

```text
outputs/reports/error_analysis.json
outputs/reports/error_analysis.txt
```

The report includes:

- scope
- error categories
- robustness-case counts
- representative failures
- critical-field consequences
- real-data observations
- evaluator findings
- limitations

## Important interpretation

The report explicitly distinguishes synthetic robustness evidence from real-data observations.

Representative synthetic failures are evidence about controlled sensitivity. They are not estimates of real-world OCR error rates.

Real-data observations are confidence/page-quality signals because authoritative assignment ground truth is unavailable.

## Production-oriented findings

The current analysis highlights that:

- aggregate metrics can hide critical-field failures;
- identifier corruption deserves separate attention;
- confidence requires contextual interpretation;
- field-level consequences complement CER/WER;
- reporting should preserve limitations instead of overstating accuracy.
